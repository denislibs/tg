# Инструменты паритета с tweb

Три скрипта, которые отвечают на вопрос «совпало или нет» без чтения исходников глазами.
Дополняют базу знаний [`docs/tweb/`](../../docs/tweb/README.md): док говорит, **как** в tweb,
скрипт — **что у нас разошлось**.

Путь к исходникам tweb берётся из `TWEB_DIR` (по умолчанию `/Users/denisurevic/Documents/tweb`).

## `inventory.mjs` — что в tweb есть и сколько доехало

```bash
node tools/tweb-parity/inventory.mjs
```

Перегенерирует [`docs/tweb/inventory/`](../../docs/tweb/inventory/):

| Файл | Что внутри |
|---|---|
| `coverage.md` | сводка для человека: дыры по файлам стилей, отстающие партиалы, попапы без пары |
| `styles.json` | по каждому scss-файлу tweb: портирован ли, покрытие классов, полный список недостающих |
| `classes.json` | все CSS-классы tweb с пометкой, встречаются ли они у нас (в scss или в коде) |
| `popups.json` | попапы tweb и сопоставление с нашими компонентами |

Гонять после каждого этапа порта — цифры покрытия и есть отчёт о прогрессе.

**Что значит «встречается у нас».** Имя класса найдено в наших `.scss` или в коде компонентов.
Это признак наличия, а не паритета: класс может быть, а вёрстка вокруг него — другой.

## `scss-parity.mjs` — дифф селекторов портированных стилей

```bash
node tools/tweb-parity/scss-parity.mjs --all          # сводка по всем 69 общим файлам
node tools/tweb-parity/scss-parity.mjs _chatBubble.scss   # полный дифф одного
```

Разворачивает вложенность и `&`, сравнивает итоговые селекторы. Значения свойств не
сравниваются — цель найти пропущенные состояния и ветки (`.bubble.is-out .time`,
`.is-selecting &`), а не расхождения в пикселях.

Ноль расхождений — нормальное состояние: стили портированы файлами. Скрипт нужен, чтобы
поймать момент, когда файл поправили руками и он поехал от оригинала.

## `dom-parity.mjs` — сверка нашего DOM с эталонным дампом

```bash
# 1. открыть нужный экран на стенде (во встроенном браузере — с ?noSharedWorker=1)
# 2. выполнить в консоли содержимое snapshot-dom.js, затем:
#    __snapshotDom('#main-columns', 5)
# 3. сохранить вывод в файл и сравнить с эталоном:
node tools/tweb-parity/dom-parity.mjs 01-skeleton /tmp/ours.txt
```

Эталоны — 135 дампов живого `web.telegram.org/k` в
[`docs/tweb/dom/dumps/`](../../docs/tweb/dom/dumps/); первый аргумент можно указать
именем дампа без расширения.

Отчёт делится на три части:

- **классы эталона, которых у нас нет** — обычно это и есть баг;
- **классы с другим родителем** — вёрстка та же, а вложенность разъехалась;
- **наши классы, которых нет в эталоне** — самодеятельность или ещё не выпиленный старый слой.

Сравниваются тег, классы и вложенность. Атрибуты, тексты и порядок соседей игнорируются:
в дампах это данные живого аккаунта, их совпадение ничего не значило бы. Хешированные
имена CSS-модулей (`_ListContainer_176w2_77`) отбрасываются с обеих сторон.

Код возврата: `1`, если есть недостающие или переехавшие классы, — годится для CI.

```bash
node --test "tools/tweb-parity/**/*.test.mjs"
```
