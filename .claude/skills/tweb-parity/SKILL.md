# Паритет с tweb: читать базу знаний до кода

Правило проекта (`CLAUDE.md`): вёрстка и поведение берутся **1:1 из tweb**, не выдумываются.
Чтобы не перечитывать исходники tweb каждый раз, в `docs/tweb/` лежат готовые референсы —
10 000+ строк с `файл:строка` по tweb и секциями «у нас» с уже найденными расхождениями.

**Никогда не пиши разметку, классы, анимации или поведение по памяти.** Сначала док, потом
исходники tweb (`/Users/denisurevic/Documents/tweb`), потом код.

## Порядок работы

1. **Определи подсистему** — по таблице симптомов ниже или по таблице подсистем. Читай не
   весь док, а нужные разделы: целиком каждый — 20–36 тыс. токенов.
2. **Проверь, есть ли это у нас вообще.** `docs/tweb/inventory/coverage.md` — сводка покрытия:
   какие файлы стилей tweb к нам не доехали и сколько классов отсутствует. «Пустой экран»
   и «поехала вёрстка» часто значат, что стилей просто нет, и читать док про поведение рано.
3. **Точечный это фикс или платформа?** `docs/tweb/roadmap.md`: если симптом там описан как
   следствие отсутствующего механизма (навигационный стек, базовый попап, слайдер табов,
   wrappers, конвейер ленты) — скажи об этом пользователю до того, как чинить точечно.
   Точечная починка симптома платформы разъезжается снова.
4. **В исходники tweb** иди только за тем, чего нет в доке; в доке уже есть точные адреса.
5. **Пиши код**, следуя разметке и классам tweb. Стили в `web-client/src/styles/tweb/`
   портированы глобально — не заводи CSS-модули для того, что там есть.
6. **Сверь результат скриптами** (см. «Инструменты» ниже), а не глазами по скриншоту.
7. **Обнови секцию «у нас»** в референсе, который использовал, — в том же изменении.
   Перегенерируй инвентарь, если портировал стили.
8. **Проверь** до слова «готово»: сборка, тесты, поведение в браузере.

## Инструменты сверки

Подробности — `tools/tweb-parity/README.md`.

```bash
node tools/tweb-parity/inventory.mjs                      # перегенерировать покрытие
node tools/tweb-parity/scss-parity.mjs _chatBubble.scss   # дифф селекторов с оригиналом
node tools/tweb-parity/dom-parity.mjs 01-skeleton ours.txt  # дифф нашего DOM с эталоном
```

DOM снимается на стенде через `tools/tweb-parity/snapshot-dom.js` (в консоли:
`__snapshotDom('#main-columns', 5)`). Эталоны — 135 дампов живого Telegram в
`docs/tweb/dom/dumps/`. Скрипт покажет, каких классов нет и у каких изменился родитель, —
это быстрее и точнее, чем сравнивать скриншоты.

## Как портировать платформу

Механизмы из `roadmap.md` (навигационный стек, попап, слайдер, wrappers, конвейер ленты)
**портируются файлом, а не идеей**. Чистая логика tweb — `positionMenu`, `ScrollSaver`,
`getViewportSlice`, `superIntersectionObserver`, тайминги и константы переходов — не завязана
на MTProto: её копируем почти дословно и адаптируем только точки входа. Переписывание
«по-реактовому» каждый раз рождает новое расхождение, а вместе с ним следующий баг-репорт.

Своё пишем там, где различие осознанное и записано в `roadmap.md` («Что в план НЕ входит»).

## Если дока нет

Не додумывай по аналогии. Исследуй tweb, **запиши новый док** по конвенциям из
`docs/tweb/README.md` (короткое имя по подсистеме, ссылки `файл:строка`, секция «у нас»
и чеклист проверки в конце, строка в индексе) — и только потом пиши код. Иначе следующая
задача по этой теме начнётся с нуля.

## Частые ловушки

- **Инлайновый стиль перебивает портированный CSS.** Прежде чем ставить `style={{...}}`,
  проверь, нет ли уже правила в `styles/tweb/` — так уехали sticky-табы shared media.
- **«Класса нет» ≠ «класс не нужен».** Проверь по `inventory/classes.json`, где он в tweb:
  часто отсутствует целый партиал, а не одно правило.
- **Различия user/group/channel в tweb декларативные**, а не форки: каждая секция профиля
  сама решает, показываться ли. Не плоди ветвления по типу пира.
- **Порядок в DOM вместо `z-index`.** В tweb у попапов, меню и медиавьювера один `z-index: 4`;
  ручные числа 500…9999 — наш долг, не образец.
- **`framer-motion` и MUI удалены** — не возвращать: анимации на CSS-классах tweb.
- **Виртуальный список диалогов уже портирован** (программа из 4 этапов) — не переизобретать,
  спеки в `docs/superpowers/specs/2026-08-1[23]-*`, читать разделы «Отступления».
