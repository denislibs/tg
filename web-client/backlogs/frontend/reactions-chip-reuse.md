# Ряд реакций пересобирается целиком — чипы не переиспользуются

**Статус:** открыт, долг назван (не закрыт кодом).
**Дата фиксации:** ветка `fix/reactions-limit-and-echo`, при починке
«анимация реакции то играет, то нет» — 2026-09-06.
**Контекст:** второй пересбор на СВОЙ клик уже снят (эхо кадра, описывающее
уже применённое состояние, больше не порождает операцию —
`core/managers/messages/reactionMethods.ts::cacheReaction`,
пин `components/chat/bubbles.reactionEcho.test.ts`). Осталась причина, по
которой ЛЮБОЙ пересбор вообще опасен для анимации.

## Что у нас

Ряд реакций строится ЗАНОВО на каждое обновление сообщения:

- `components/chat/bubbles.ts:2008-2012` — прошлый `.reactions` забирается в
  `previousReactions` и тут же удаляется из DOM;
- `bubbles.ts:2072-2083` — `createReactionsElement` строит НОВЫЙ контейнер,
  а `previous` едет только источником данных (`data-count`, `is-chosen`);
- `components/chat/reactions.ts:861-871`, `:576-606` — новый `div.reactions` и
  новый `div.reaction` на каждый `ReactionCount`; переиспользования нет по
  построению (файл это сам признаёт — докблок `reactions.ts:549-558`).

Одной воронкой `message_edit` сюда приходят чужая реакция, `media_read`,
factcheck и правка текста (докблок `bubbles.ts:5462-5471`), то есть ряд
пересобирается заметно чаще, чем меняется.

## Чем это платится

1. **Анимация реакции.** Эффект держит `stickerContainer` СТАРОГО чипа
   (`reactions.ts:734`), а `components/wrappers/stickerAnimation.ts:141-163`
   покадрово снимает полёт по `!isInDOM(target)`. Любой пересбор во время
   полёта гасит анимацию молча.
2. **Мигание иконки чипа.** `reactions.ts:466-467` кладёт текстовое эмодзи
   синхронно, снимается оно только после `wrapSticker(...).render`
   (`:524`), а `lib/lottie/lottieLoader.ts:271-290` каждый раз создаёт НОВЫЙ
   wasm-плеер и заново парсит анимацию (реюз по `cacheName` работает только
   при `params.sync`, `:240-258`, а `wrapSticker` его не передаёт). Отсюда
   видимое «эмодзи → канва» на каждом пересборе. Починкой эха это ушло
   ТОЛЬКО для собственного клика (пересбор один вместо двух) — на чужие
   обновления мигание осталось.
3. **Накопительная утечка плееров.** `bubbles.ts:862` — один
   `middlewareHelper` на весь чат, он же раздаётся чипам (`:2077`, `:2673`);
   `animationIntersector.ts:358-364` у `controlled`-плеера удаления «вышел из
   DOM» не делает вовсе. Отсоединённые плееры остаются в
   `byPlayer`/`byGroups`/`byElement` до уничтожения ЧАТА.
4. **Переход `is-chosen` никогда не играет.** `reactions.ts:560-567` —
   `duration: chip.isConnected ? 300 : 0`, а чип создаётся отсоединённым
   (`:576`), значит выражение всегда даёт 0 (у tweb второй вызов застаёт узел
   подключённым — `reaction.ts:1093`).

## Как в оригинале

`tweb/src/components/chat/reactions.ts:279-360` — ряд ОБНОВЛЯЕТСЯ, а не
пересобирается:

- `:291-296` снимаются только ИСЧЕЗНУВШИЕ чипы (и там же `destroy()` их
  собственного middleware — `:312-315`, свой `middleware.create()` на каждый
  `ReactionElement`);
- `:310-318` существующий чип ищется по значению реакции (`reactionsEqual`),
  новый создаётся только если не нашёлся;
- `:358-360` порядок доводится `positionElementByIndex`;
- иконка чипа wrap-ится РОВНО ОДИН РАЗ за жизнь чипа —
  `tweb/src/components/chat/reaction.ts:782-800` (гейт `hadStickerContainer`),
  и это РАСТР (`static: true`, `reaction.ts:894`), то есть в
  `animationIntersector` вообще не попадает.

## Что делать

1. ДО порта снять латентную мину: `reactions.ts:624-629` (`getChangedResults`)
   читает `is-chosen` без терма `!backwards`, в отличие от `:562`
   (`setIsChosen`). Пока `duration === 0` — безвредно, станет ложным
   срабатыванием ровно тогда, когда переход оживёт.
2. `createReactionsElement` → `updateReactionsElement` (порт tweb
   `reactions.ts:279-360`): снимать только исчезнувшие, искать по
   `reactionKey`, `positionElementByIndex`, «иконка один раз», свой
   `middlewareHelper.create()` на чип.
3. Точка вызова `bubbles.ts:2008-2012` и `:2072-2099` — передавать ЖИВОЙ узел
   на обновление вместо `remove()`, сохранив идемпотентность
   `renderMessageMeta` и ветку `has-floating-time` (время у медиа-бабла
   переезжает внутрь контейнера реакций, `:2084-2099`).

**Риск по тестам — высокий:** `components/chat/reactions.test.ts` местами
пинует именно «собирается заново» (`:179`, `:465`, `:475`), плюс
`bubbles.meta/reactionClick/savedReaction/hoverReaction`.

**Критерий готовности:** на обновление сообщения узлы существующих чипов
переживают перерисовку (в `bubbles.reactionEcho.test.ts` — та же проверка
идентичности узла, но и для ЧУЖОГО кадра), иконка чипа не перезагружается,
переход `is-chosen` играет 300 мс.
