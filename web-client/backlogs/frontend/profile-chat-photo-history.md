# Карусель аватаров группы/канала — только текущее фото, без истории

**Статус:** открыт, долг назван (не закрыт кодом).
**Дата фиксации:** волна 3 «Solid-миграция», программа `docs/superpowers/
plans/2026-09-05-profile-avatars-class.md`, задача 2 (данные и лента
`PeerProfileAvatars`).
**Контекст:** `components/peerProfileAvatars.ts::setPeer` — ветка не-юзера
(группа/канал). Список фото (`items`) заводится ТОЛЬКО для `isUser(peerId)`;
для группы/канала `items` всегда `[]`.

## Что в tweb

`ListLoader.loadMore` для чата/канала (`peerProfileAvatars.ts:443-499`) грузит
историю через `appMessagesManager.getHistory({peerId, inputFilter:
{_: 'inputMessagesFilterChatPhotos'}, ...})` — то же API истории сообщений,
отфильтрованное на служебные сообщения о смене фото
(`filterChatPhotosMessages`). Плюс `appProfileManager.getChatFull` за
`chat_photo` для самого первого (текущего) элемента, если его нет среди
сообщений (`generateFakeAvatarMessage`). Это даёт полноценную карусель
ПРОШЛЫХ аватарок группы/канала, а не только текущий.

## Чего нет у нас

Ручки истории фото группы/канала нет вовсе — `GET /users/{id}/photos`
(`profileManager.ts:110`) существует только для пользователей
(`profile_handler.go:438-461`: `ListPhotos` читает `chi.URLParam(r,
"userID")` и уходит в `ListProfilePhotos`, которая по построению — таблица
`profile_photos`, привязанная к пользователю, а не к чату). У истории
сообщений (`GET /chats/{id}/history`) нет фильтра «только смена фото»
(`inputMessagesFilterChatPhotos` на нашем проводе не существует).

## Что делает `setPeer` сегодня

Для не-юзера `items = []`, поэтому `current` (первый элемент листаемой ленты)
всегда `undefined` — но `SHOW_NO_AVATAR` всё равно рисует ОДИН узел через
`avatarNew({peerId, ...})` (тот же зеркальный путь, что рисует аватар пира
везде в приложении): это и есть «текущее фото», просто без карусели истории.
Визуально для группы/канала БЕЗ фото и группы/канала С фото поведение сегодня
идентично коду (различие только в том, что рисует зеркало пира внутри
`avatarNew`) — карусель, стрелки, полоски-индикаторы никогда не появляются
(`is-single` всегда true, т.к. `addTab()` вызывается ровно один раз).

## Что делать

1. Завести ручку истории фото чата на бэкенде: либо фильтр
   `?filter=chat_photos` у `GET /chats/{id}/history`, либо отдельная
   `GET /chats/{id}/photos` по аналогии с пользовательской. Модель —
   `chat_photo_history` (аналог `profile_photos`, но по `chat_id` и без
   владельца-загрузчика) или пересчёт из уже существующих служебных
   сообщений о смене фото (если они пишутся в `messages`).
2. `profileManager.ts` — метод вида `listChatPhotos(chatId)` рядом с
   `listPhotos`.
3. `peerProfileAvatars.ts::setPeer` — для `!isUser(peerId)` завести
   отдельную ветку `loadMore`, зеркальную пользовательской, вместо
   `items = []`.

**Критерий готовности:** открытие профиля группы/канала с историей смен фото
показывает карусель из нескольких элементов (полоски, стрелки), а не только
текущее фото; тест на `peerProfileAvatars.test.ts` заводит фейковый
`listChatPhotos` с несколькими фото и проверяет число узлов `.profile-
avatars-avatar`, как это уже делает пользовательский тест «N фото → N
узлов».
