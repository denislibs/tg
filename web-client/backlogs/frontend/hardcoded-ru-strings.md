# Русский текст литералом в исходниках — интерфейс говорит на двух языках

**Статус:** открыт, долг под рэтчетом.
**Дата фиксации:** 2026-09-07, ветка `fix/visible-cleanup`.
**Пин:** `web-client/src/i18n/noHardcodedStrings.test.ts` (`DEBT` — точные числа
по файлам).

## Симптом

На браузере с локалью `en-US` (в хранилище клиента лежит пакет с
`lang_code: "en"`) интерфейс наполовину русский: подписи опроса идут
по-английски («Anonymous Poll», «8 members voted»), а шапка чата — по-русски
(«0 подписчиков»).

## Корень — НЕ «два способа выбора языка»

Выбор языка у нас ОДИН и работает верно:

* владелец факта — `I18n.lastRequestedLangCode` (`src/lib/langPack.ts:239`),
  читается синхронно на импорте из `localStorage['tg-lang']`, умолчание
  `DEFAULT_LANG_CODE = 'en'` (`:186`);
* наполняет `I18n.strings` ровно один путь — `applyLangPack` (`:535-582`),
  локальный английский (`src/lang.ts`) ложится ПОД серверный пакет
  (`applyServerLangPack`, `:360-377`);
* язык браузера — только ПРЕДЛОЖЕНИЕ и только когда выбора ещё не было
  (`suggestBrowserLangCode`, `:1034-1044`), порт tweb `languageChangeButton.tsx`;
* сервер язык не выбирает вовсе: `GET /langpack/{langCode}` берёт код ИЗ ПУТИ
  (`backend/internal/adapter/delivery/http/langpack_handler.go:53-68`),
  `Accept-Language` не читается нигде — ни в бэкенде, ни в клиенте;
* React-зеркало (`src/i18n/index.tsx`) своего словаря и своего выбора не имеет:
  `setLang` только объявляет выбор ядру (`:78`).

Разнобой даёт ВТОРОЙ, теневой слой: **строки, написанные литералом мимо
словаря**. Опрос идёт через ядро (`I18n.i18n('Chat.Poll.Type.Anonymous')`) и
честно показывает язык пакета; шапка чата словаря не спрашивала вовсе:

```ts
// components/Chat.tsx:869 (до правки)
if (isBroadcast(chatPeer)) return `${members} подписчиков`
```

Такая строка русская ВСЕГДА. Ни один из двух прежних пинов её не видел:
`noHandPickedLanguage.test.ts` ловит ветвление `lang === 'ru'`, а ветвления тут
нет; `noBrowserLocaleDates.test.ts` — про даты.

## Порядок закрытия

1. `core/serviceMsg.ts` — самый заметный на экране (лента) и самый большой; у
   оригинала это `wrappers/messageActionTextNew.ts` с готовыми ключами.
2. `core/hooks/useTypingLabel.ts` и `components/folders/labels.ts` — снос
   мини-словарей (ключи `Peer.Typing*` / фильтры папок есть у оригинала).
3. `components/userInfo/helpers.ts` — счётчики; часть уже решена
   `wrappers/getChatMembersString.ts`, остальное — числовые ключи оригинала.
4. `core/messageToConvMsg.ts` — превью вложений (`Message.Photo`, `AttachVideo`…).
5. Остальные экраны — по одному, каждый со своей сверкой ключей с tweb.

Каждый шаг обязан уменьшить число в `DEBT`: пин сверяет его ТОЧНО, поэтому
«починил и забыл обновить» тоже краснеет.

## Отдельный, не входящий в это число долг

`components/emoji/emojiData.ts` — 106 двуязычных ПОИСКОВЫХ ключевых слов
(`NAMES`). Они не показываются, поэтому в `NOT_UI`, а не в `DEBT`. Но предмет
реальный: у tweb ключевые слова эмодзи приезжают с сервера per-язык, у нас
лежат локально одним списком «en + ru» — немецкий пользователь ищет эмодзи
по-английски и по-русски. Ручки «ключевые слова по языку» у нас нет вовсе;
заводить её — отдельная работа со своим бэкендом.

## Почему пин сканирует РАЗБОРОМ, а не регуляркой

Первая редакция скана снимала комментарии двумя `replace`, как соседний
`noHandPickedLanguage.test.ts`. На `Chat.tsx` это ЗАБЕЛИЛО настоящий код:
последовательность `/*` внутри однострочного комментария открывает фальшивый
блочный комментарий до ближайшего `*/`, и скан молчал ровно про ту строку, ради
которой заводился. Поэтому в пине минимальный разбор: комментарии обоих видов,
регэксп-литералы и подстановки `${…}` — не текст. У соседнего пина та же
слабость; она там пока не выстрелила из-за узости его шаблона.
