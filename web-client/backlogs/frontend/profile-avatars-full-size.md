# Первый элемент карусели аватаров — фиксированный размер 120 вместо `avatar-full`

**Статус:** открыт, долг назван (не закрыт кодом). Визуальный, не
поведенческий — DOM-факты (число узлов, `.active`, переходы) не зависят от
этого долга, поэтому он не блокирует тесты задачи 2.
**Дата фиксации:** волна 3 «Solid-миграция», программа `docs/superpowers/
plans/2026-09-05-profile-avatars-class.md`, задача 2 (данные и лента
`PeerProfileAvatars`).
**Контекст:** `components/peerProfileAvatars.ts::processItem` — ветка
«первый элемент ленты» (`isFirst || !photo`, tweb `:836-841`).

## Что в tweb

Первый элемент карусели (мирроr текущего аватара пира) рисуется
`avatarNew({size: 'full', isDialog: false, isBig: true, noFadeIn: true, ...})`
(`peerProfileAvatars.ts:824-833`). Класс `avatar-full` (`_avatar.scss:447`)
растягивает узел на 100% ширины/высоты родителя (`.profile-avatars-avatar`,
`_profile.scss:121-130`: `min-width:100%; padding-bottom:100%; position:
relative`) — фотография заполняет весь квадрат ленты, а не фиксированный
пиксельный кружок.

## Чего нет у нас

`components/avatar.ts` (`AvatarOptions.size`) принимает **только число** —
у него уже задокументирован этот вычет («`size: 'full'`… — вызывающих
нет», см. докблок файла). Расширение контракта — изменение самого
`avatar.ts`, а он вне периметра задачи 2 плана (файлы задачи —
`peerProfileAvatars.ts` и её тест). Поэтому `processItem` передаёт
фиксированный `size: 120` — тот же приём, что уже применён к ветке топика
(задача 1, `avatarNew({peerId, size: 120})`, tweb-оригинал которой тоже
использует 120, а не `'full'` — там расхождения нет; расхождение именно в
ЭТОЙ, обычной ветке карусели).

## Эффект

Первый (текущий) аватар в развёрнутой карусели профиля рисуется кружком
120px по центру квадратной ленты вместо фотографии, растянутой на весь
квадрат. Остальные элементы ленты (исторические фото, `<img>`/`<video>`
напрямую) уже растягиваются на 100% через собственную разметку — сравнение
первого элемента с остальными будет визуально заметным (первый — заметно
меньше).

## Что делать

Расширить `AvatarOptions.size` в `components/avatar.ts` до `number | 'full'`
и завести обработку в `apply()`/конструкторе узла: класс `avatar-full`
вместо `avatar-{size}`, без установки `--size`/`--multiplier` (или с
разумным дефолтом для инициалов, которые `avatar-full` не масштабирует
через `--multiplier` — сверить с `_avatar.scss:447-458`, там `.avatar-full`
не переопределяет `font-size`, значит инициалы возьмут дефолтный
`--multiplier: 1`, что тоже может потребовать отдельного разбора). После
этого `processItem` меняет `size: 120` на `size: 'full'` — строка с этим
комментарием.

**Критерий готовности:** первый элемент карусели профиля визуально
заполняет квадрат ленты, как остальные элементы; юнит-тест на `avatar.ts`
проверяет класс `avatar-full` при `size: 'full'`.
