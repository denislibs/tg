# Удаление фото профиля не работает с клиента: ручка ждёт id строки, а наружу отдаётся id медиа

**Статус:** открыт. Найдено 2026-09-05 при живой проверке шапки профиля
(порт `PeerProfileAvatars`, план `docs/superpowers/plans/2026-09-05-profile-avatars-class.md`).

## Симптом

`DELETE /api/me/photos/{photoID}` отвечает `200 {"_":"boolTrue"}`, но фото
остаётся в галерее: следующий `GET /api/users/{id}/photos` возвращает его же.

Воспроизведено на стенде дважды подряд, с паузой между вызовами (не кэш).

## Причина

Разные адресные пространства по обе стороны ручки:

- `AuthRepo.DeleteProfilePhoto`
  (`backend/internal/adapter/repo/postgres/authrepo.go:305-316`) удаляет
  **по id строки**: `DELETE FROM profile_photos WHERE id=$1 AND user_id=$2`.
- Наружу же список отдаёт **id медиа**: `galleryPhoto()` в
  `backend/internal/adapter/delivery/http/profile_handler.go` кладёт в
  конструктор `photo` идентификатор файла, и клиентский маппер это фиксирует —
  `mapProfilePhoto` (`web-client/src/core/managers/profileManager.ts:141`)
  пишет `{ id: p.id, mediaId: p.id }`, то есть `id === mediaId`.

Клиент никогда не узнаёт id строки, поэтому передать в удаление ему нечего.
Промах при этом **молчаливый**: удаление неизвестной строки — задокументированный
no-op, возвращающий текущую аватарку без изменений
(комментарий там же, `authrepo.go:300-304`), а ручка поверх него всё равно
отвечает `boolTrue` (`profile_handler.go:465-481`).

## Что делать

Свести адресацию к одному виду — по образцу остальных наших ручек, где наружу
уходит ровно один идентификатор на сущность:

- либо `DELETE /me/photos/{mediaID}` удаляет по `media_id` (тогда правится SQL
  и имя параметра),
- либо галерея отдаёт id строки, а не файла (тогда правится `galleryPhoto()` и
  клиентский маппер).

Первый вариант ближе к тому, что уже есть у клиента, и не трогает витрину.

Отдельно: ручка обязана отвечать честно. «Удалили ноль строк» — это не
`boolTrue`; нужен 404 (или явный признак в ответе), иначе любой сбой адресации
снова окажется невидимым.

## Критерий готовности

Загрузить фото профиля, удалить его тем идентификатором, который клиент реально
получает из `GET /users/{id}/photos`, и убедиться, что список после этого пуст.
Плюс тест на «удаление несуществующего id не отвечает успехом».
