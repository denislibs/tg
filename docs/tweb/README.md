# База знаний по tweb: что читать перед портом

Референс — **tweb** (Telegram Web K), исходники: `/Users/denisurevic/Documents/tweb`.
Правило проекта: любую вёрстку/поведение берём 1:1 из tweb, не выдумываем
(см. [`../../CLAUDE.md`](../../CLAUDE.md)). Эти доки существуют, чтобы **не перечитывать tweb каждый раз**.

**Что портировать и в каком порядке** — [`roadmap.md`](roadmap.md)
(сводный план: расхождения из всех доков сведены к пяти платформам).

## Как пользоваться

1. Берёшься за экран/подсистему — открой её строку в таблице ниже и прочитай указанный док.
   Маршрут по симптому («модалка не закрывается по Esc», «таб теряет скролл») — в
   [`.claude/skills/tweb-parity/SKILL.md`](../../.claude/skills/tweb-parity/SKILL.md).
2. Проверь по [`inventory/coverage.md`](inventory/coverage.md), есть ли подсистема у нас вообще:
   пустой экран часто значит, что партиал стилей не портирован, и читать про поведение рано.
3. В каждом доке есть секция «у нас» с расхождениями и картой наших файлов, а в конце —
   чеклист «Проверка после порта».
4. Результат сверяй скриптами из [`tools/tweb-parity/`](../../tools/tweb-parity/README.md),
   а не скриншотами.
5. Если дока нет — сначала исследование (пиши новый док сюда), потом код.

## Машинные срезы

[`inventory/`](inventory/) генерируется из исходников tweb — `node tools/tweb-parity/inventory.mjs`.

| Файл | Что отвечает |
|---|---|
| `coverage.md` | сводка: какие партиалы стилей не доехали, где отставание больше всего, попапы без пары |
| `styles.json` | по каждому scss-файлу tweb: портирован ли, покрытие, полный список недостающих классов |
| `classes.json` | все CSS-классы tweb с пометкой, встречаются ли они у нас |
| `popups.json` | попапы tweb и сопоставление с нашими компонентами |

Руками не править — перегенерируется. Цифры покрытия и есть отчёт о прогрессе порта.

## Соглашения

**Где что лежит.** Здесь, в `docs/tweb/`, — справочник: доки живут долго, обновляются по мере
портирования, поэтому имена короткие и без дат (`bubbles.md`, `popups.md`). Рядом в
[`../research/`](../research/) — снимки во времени (аудиты расхождений, разборы наших подсистем);
там дата в имени и есть смысл файла, такие доки не обновляются, а заменяются новыми.

**Новый док в справочник:**

- имя — по подсистеме, латиницей, без даты;
- в шапке: когда снято, источники (путь к tweb + коммит, если важен), пометка про форк;
- ссылки на код — всегда `файл:строка`; таблицы вместо простыней текста;
- секция «у нас» в конце: карта наших файлов + расхождения;
- следом чеклист «Проверка после порта»: 6–10 пунктов, которые можно прощёлкать на стенде,
  и ссылка на подходящие дампы для `dom-parity.mjs`;
- не дублировать существующие доки — ссылаться;
- добавить строку в таблицу выше и, если подсистема крупная, в
  [`.claude/skills/tweb-parity/SKILL.md`](../../.claude/skills/tweb-parity/SKILL.md).

**Правило поддержки.** Портируешь подсистему — обновляешь её секцию «у нас» в том же изменении.
Иначе справочник протухает и им перестают пользоваться.
