# Этап 4: остальные списки на то же ядро

**Дата:** 2026-08-13
**Статус:** дизайн согласован
**Родительская спека:** [`2026-08-12-dialogs-ownership-and-virtual-list-design.md`](2026-08-12-dialogs-ownership-and-virtual-list-design.md)
**Предыдущий этап:** [`2026-08-13-virtual-chatlist-design.md`](2026-08-13-virtual-chatlist-design.md)

## Поправка к родительской спеке

Родительская спека называла для этапа 4 «`SearchView` (itemSize 72) и
`TopicsPanel` (itemSize 64)». Проверка исходников tweb это НЕ подтвердила —
`SearchView` названо ошибочно. Фактические потребители ядра
`SortedDialogList`/`createDeferredSortedVirtualList` в tweb:

| Потребитель tweb | Файл | `itemSize` | Что это у нас |
|---|---|---|---|
| Архивные чаты | `sidebarLeft/tabs/archivedTab.tsx` (`AutonomousDialogList`, `FOLDER_ID_ARCHIVE`) | 72 | оверлей архива, `Sidebar.tsx:339-347` |
| Темы форума | `forumTab/groupForumTab.ts:27-32` (`itemSize: 64, noAvatar: true`) | 64 | `components/TopicsPanel.tsx` |
| Избранное (Saved) | `appSearchSuper.ts:1897-1907` (`itemSize: 72, extraPaddingBottom: 0`) | 72 | список в `userInfo/SharedMedia.tsx` |
| Монофорум/ботфорум | `forumTab/monoforumTab.ts`, `botforumTab.ts` | 72 | функциональности нет |

Обычные результаты поиска (чаты, глобальный поиск, сообщения, медиа, ссылки,
файлы, музыка, голосовые) в `appSearchSuper` через это ядро НЕ идут — там
секции с заголовками и медиа-грид, а ядро умеет только однородные строки
фиксированной высоты. `SearchView` в этом этапе не трогаем: виртуализировать
его — не порт, а выдумка.

Значение `72` из `appSearchSuper` относится к вкладке «Избранное», а не к
поиску вообще; отсюда и ошибка в родительском наброске.

## Задача

Перевести на ядро этапа 3 три списка: архив, темы форума, избранное. Ни один
из них не нуждается в пагинации: архив живёт в зеркале целиком, темы и
избранное грузятся одним RPC. Ядро это допускает — `DeferredSortedVirtualList`
принимает `items`/`totalCount` пропами, а `requestItemForIdx` для непагинируемого
списка ничего не делает.

## Наше состояние

| Список | Где | Как рендерится сейчас |
|---|---|---|
| Архив | `Sidebar.tsx:339-347` | `archivedChats.map(...)` в `div.archiveList` со своим `overflow-y: auto` (`Sidebar.module.scss:126-141`); без `ul.chatlist` |
| Темы форума | `TopicsPanel.tsx:279-298` | `visible.map(renderRow)` + сворачиваемая секция `hidden.map(...)` в `div.list` (`TopicsPanel.module.scss:26-34`); `renderRow` — функция ВНУТРИ компонента, не мемоизированный компонент; строка `min-height: 64px` |
| Избранное | `userInfo/SharedMedia.tsx` | список из `useSavedDialogs` |

## Решение

### Архив (itemSize 72)

Самый прямой перенос: строки — те же `ChatListItem`, данные — то же зеркало
(`archivedChats`), ядро — то же, что у основного списка. Отличия от основного:
нет закреплённых элементов, нет пагинации (`totalCount = items.length`,
`isEnd = true`), пустое состояние («No archived chats») остаётся.

### Темы форума (itemSize 64, `noAvatar`)

Два подсписка в одном контейнере — видимые темы и свёрнутая секция скрытых.
Ядро умеет один плоский список фиксированной высоты, поэтому:

- виртуализируется ТОЛЬКО список видимых тем;
- секция скрытых остаётся обычным потоком под ним. Причина: у неё есть свой
  заголовок-раскрывашка и она по определению короткая (скрытые темы —
  единицы), а вклинивать разнородный узел в список фиксированной высоты ядро
  не умеет и в tweb такого нет.

`renderRow` из тела `TopicsPanel` выносится в отдельный мемоизированный
компонент `TopicRow` — иначе каждая перерисовка панели пересоздаёт все строки,
и мемоизация окна не работает. `noAvatar: true` — как в `groupForumTab.ts:29`.
Контейнеру ставится класс `topic-dialogs-override` (`groupForumTab.ts:23`) —
проверить, есть ли под него стили в наших `styles/tweb/`, и если нет, привезти
их из tweb вместе с переносом.

### Избранное (itemSize 72, `extraPaddingBottom: 0`)

`extraPaddingBottom: 0` — буквально из `appSearchSuper.ts:1906`: этот список
вложен в панель профиля, лишние 8px снизу там не нужны.

## Отступления от tweb

1. **Секция скрытых тем не виртуализируется** (см. выше). В tweb скрытые темы
   живут в том же `SortedDialogList`; у нас они вынесены в отдельную
   сворачиваемую секцию — это отступление СУЩЕСТВУЮЩЕЕ, не вводимое этим
   этапом, и трогать его здесь не будем: перекраивать поведение панели заодно с
   виртуализацией — смешивать две задачи.
2. **`SearchView` не трогаем** — см. «Поправку» выше.
3. **Строка «Избранного» выросла 56 → 72px** (`.savedRow { min-height: 72px }`,
   `userInfo/SharedMedia.module.scss`). Ядро раскладывает строки абсолютом с
   ШАГОМ `itemSize`, а значение оригинала — `itemSize: 72`
   (`appSearchSuper.ts:1905`, `loadSavedDialogs`: строки этой вкладки — обычные
   строки списка диалогов, `.row-big { min-height: 4.5rem }`). Совместить шаг 72
   с прежней высотой 56 НЕЛЬЗЯ: либо строка не заполняет свой слот (16px дыры
   между строками), либо шаг ставится 56 — то есть значение оригинала не
   портируется. Выбрано значение оригинала; это и есть то видимое изменение,
   из-за которого поправлен критерий приёмки №2.
4. **`extraPaddingBottom: 0` у ТЕМ форума.** Спека называла этот проп только для
   «Избранного» (`appSearchSuper.ts:1906`); у tweb'ского `groupForumTab.ts` его
   нет. Причина у нас своя, но того же рода: нижний клиренс уже даёт
   `padding-bottom` контейнера прокрутки (`.list`), а СРАЗУ за `ul` в потоке
   идёт секция скрытых тем — дефолтные 8px ядра
   (`deferredSortedVirtualList.tsx:55`) сдвинули бы её заголовок, то есть дали
   бы видимое изменение панели. Обоснование продублировано у самого пропа
   (`TopicsPanel.tsx`).
5. **Класс `topic-dialogs-override` НЕ привезён.** Спека («Решение», темы
   форума) предписывала поставить его контейнеру и, если стилей нет, привезти
   их из tweb. Правило оригинала адресовано
   `.topic-dialogs-override .chatlist-chat { min-height: 4rem }`
   (`groupForumTab.ts:23`), а `.chatlist-chat` в нашей панели тем нет вовсе:
   строка темы — собственный узел, высоту 64px он несёт сам
   (`TopicsPanel.module.scss`). Привозить правило не на кого применять — его
   селектор не совпал бы ни с одним узлом. Пометка стоит там же, в
   `TopicsPanel.module.scss`.
6. **Архивный `ul` не несёт классов `chatlist virtual-chatlist`** (в отличие от
   `ul` списка папки) — только свой модульный класс. `virtual-chatlist`
   (`_chatlist.scss:471`) переносит боковой отступ с `padding` на `margin`, и
   вместе с `chatlist` это дало бы архивным строкам боковые поля, которых у
   оверлея архива не было, — видимое изменение. Строки при этом те же
   `ChatListItem`: наследование от `ul.chatlist` им не нужно, свою разметку и
   свои классы они несут сами.

## Тесты

- `Sidebar` (архив): при 300 архивных чатах в DOM только видимые строки; пустой
  архив по-прежнему показывает заглушку.
- `TopicsPanel`: при 200 темах в DOM только видимые; высота строки 64;
  `noAvatar`; секция скрытых по-прежнему в потоке и раскрывается; `TopicRow`
  не перерисовывается при скролле, если данные не изменились.
- `SharedMedia` (избранное): виртуализирован, `extraPaddingBottom = 0`
  (высота `ul` = `count*72`, без +8).
- Скан: `SearchView` не импортирует ядро виртуализации (пин к поправке — чтобы
  следующий подход не «дописал» его по инерции).

## Критерии приёмки

1. `npm test`, `npm run typecheck`, `npm run lint` зелёные — с выводом.
2. Архив и темы визуально не изменились: те же строки, те же отступы, то же
   пустое состояние. У «Избранного» изменилась ВЫСОТА СТРОКИ — 56 → 72px, как в
   оригинале (`itemSize: 72`, `appSearchSuper.ts:1905`): совместить шаг ядра с
   прежней высотой нельзя, разбор — отступление №3. Остальное («Избранного»
   разметка строки, отступы контейнера, пустое состояние) не изменилось.
3. Скролл в каждом из трёх списков держит только видимые строки в DOM.
4. Проверено на стенде `:38080`.
