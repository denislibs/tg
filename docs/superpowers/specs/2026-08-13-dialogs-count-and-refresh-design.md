# Размер набора и `refresh()` — дизайн

**Дата:** 2026-08-13
**Предшественники:** `2026-08-13-dialogs-pagination-design.md`, `2026-08-13-virtual-chatlist-design.md`,
`2026-08-13-remaining-lists-design.md` (этапы 2–4, смержены коммитом `0d41dc41`).

## Проблема

Пагинация списка диалогов реализована и покрыта тестами, но **не работает**: первичная
загрузка `client/boot.ts` тянет весь список одним ответом, после чего `loadedAll` поднят и
`getDialogs` до конца сеанса отвечает из памяти. Причин две, и они связаны.

### 1. Размер набора известен только для «Всех чатов»

Виртуальный список рисует `totalCount` слотов; там, где элемента ещё нет, встаёт скелетон-дырка,
и она дёргает `requestItemForIdx` — **дырка и есть спусковой крючок догрузки**. Владелец отдаёт
размер так (`dialogsManager.ts::countFor`):

```ts
if (loadedAll || filterId !== ALL_FOLDER_ID) return cached.length
return serverCount ?? cached.length
```

Для архива и пользовательских папок размер = длина уже загруженного. Дырок не бывает **по
определению**, `requestItemForIdx` не срабатывает никогда. Поэтому страничный первый заход молча
усекал архив и папки до первой страницы (вплоть до пропажи строки «Архив» — гейт
`archived.length > 0` в `ChatList`), и первичная загрузка была возвращена к полной (`f2a89330`).

### 2. `refresh()` тянет весь список

`doRefresh()` бьёт в `/chats` **без параметров**. Бэкенд при `Limit <= 0` отдаёт весь набор с
`is_end: true` (`dialogpage.go:26-33`), владелец поднимает `loadedAll`. Флаг при этом выставлен
**честно** — список действительно загружен целиком; проблема не в флаге, а в том, что запрос
безлимитный. Колсайтов у `refresh()` девятнадцать (boot, deep-links, редактор контакта, resync-кадр,
Sidebar, …) — любой из них разово вытягивает всю ленту диалогов.

## Что показало исследование tweb

Первоначальная гипотеза (записана в памяти проекта и озвучена как «нужен счётчик набора по
фильтру на бэкенде») **неверна** и этой спекой отменяется. У tweb счётчика по пользовательской
папке тоже нет.

Ключ — `realFolderId` в `getDialogs` (`lib/storages/dialogs.ts:1646-1649`):

```js
// let's load only first pages by certain folderId. next pages will load without folder filtering
const realFolderId =
  (!REAL_FOLDERS.has(filterId) || this.getOffsetDate(filterId)) && !isVirtualFilter ?
    GLOBAL_FOLDER_ID :
    filterId;
```

Из этого следует модель:

- **Реальных папок две** — `FOLDER_ID_ALL = 0` и `FOLDER_ID_ARCHIVE = 1`
  (`appManagers/constants.ts:37-39`). Только они существуют на сервере.
- **Пользовательская папка — клиентский фильтр**, серверного набора у неё нет: запрос уходит с
  `GLOBAL_FOLDER_ID` (`= undefined`, т.е. вообще без папки), и `folder.count = result.count`
  (`dialogs.ts:1728`) кладёт в папку **глобальный** счётчик. Размер набора для фильтра — сознательно
  ЗАВЫШЕННАЯ оценка, а страницы вычерпывают глобальный набор, пока не поднимется `loadedAll`.
- **`loadedAll` — по реальной папке**, и это решётка (`setDialogsLoaded`, `dialogs.ts:276-299`):
  `GLOBAL` поднимает обе реальные, а обе поднятые реальные поднимают `GLOBAL`.

Наш `/chats` папку не принимает вовсе — то есть уже сейчас это ровно `GLOBAL_FOLDER_ID`.

## Решение

### Бэкенд: `/chats` учится реальной папке

Новый необязательный параметр `folder_id`: `0` — всё, кроме архива; `1` — только архив; отсутствует —
весь набор (как сегодня). Выборка режется **до** подсчёта, поэтому `count` и `is_end` относятся к
запрошенной папке. Курсор `offset_chat_id` ищется внутри той же выборки.

Домен получает тип `DialogFolder` с нулевым значением `FolderGlobal` — чтобы уже существующие
`domain.DialogPage{}` без явного поля продолжали означать «весь набор», а не «всё, кроме архива».

### Фронт: счётчик и `loadedAll` — по выборке

`serverCount` и `loadedAll` становятся записями по трём выборкам (`global`/`all`/`archive`),
`isLoaded`/`setLoaded` — дословный порт решётки `isDialogsLoaded`/`setDialogsLoaded`.

```ts
function countFor(filterId: number, cached: readonly DialogItem[]): number {
  const scope = scopeFor(filterId)
  if (isLoaded(scope)) return cached.length
  return serverCount[scope] ?? serverCount.global ?? cached.length
}
```

Пользовательская папка → `scope === 'global'` → завышенная глобальная оценка (порт `dialogs.ts:1728`).
Архив до своего первого ответа тоже опирается на глобальную оценку — она и создаёт дырку, ради
которой первый запрос вообще случается; ответ приносит настоящий `count` архива и список
подтягивается к реальности.

### Фронт: `refresh()` перечитывает удерживаемое окно

```ts
const limit = Math.max(items.length, DIALOG_LOAD_COUNT)
```

`refresh()` перестаёт быть безлимитным и перечитывает ровно столько, сколько уже держит. Свойства:

- холодный старт (`items.length === 0`) → первая страница из 20, то есть **boot становится
  страничным сам по себе**, без правок `boot.ts`;
- все девятнадцать колсайтов остаются семантически верными: они получают свежий вид того же окна,
  `setAll` над ним корректен (набор той же мощности в том же серверном порядке);
- `loadedAll` поднимается только когда сервер сказал `is_end`, то есть когда окно действительно
  накрыло набор.

## Отступления от оригинала

1. **Выборка не «схлопывается» в глобальную после первой страницы.** tweb уводит второй и
   последующие запросы реальной папки в `GLOBAL` (`dialogs.ts:1646-1649`), потому что его курсор —
   `offsetDate`, общий на все папки, и переиспользовать его между выборками дешевле, чем вести
   отдельный. Побочный эффект там же: `folder.count = result.count` (`dialogs.ts:1728`) затирает
   счётчик архива глобальным. Наш курсор — `chat_id`, он и так свой у каждой выборки, поэтому
   сохранение выборки на всех страницах ничего не стоит и убирает затирание. Отступление
   сознательное, зафиксировать комментарием у кода.

2. **`GLOBAL` не имеет отдельного бита загруженности** — он выводится как `all && archive`
   (у tweb это отдельное поле `allDialogsLoaded[GLOBAL_FOLDER_ID]`, поддерживаемое в согласии с
   двумя реальными, — то же значение, лишнее состояние).

3. **Фолбэк залипшего курсора меняется.** Сегодня `getDialogs` при непродвинувшейся странице падает
   на полный `refresh()` — «он же поднимет `loadedAll`». С ограниченным `refresh()` это рассуждение
   рушится (перечитывание того же окна не продвигает список), поэтому фолбэк становится явным:
   одна страница **без курсора** увеличенного размера (`items.length + limit`), которая гарантированно
   накрывает хвост.

## Осторожно

- `stores/noDuplicateDialogs.test.ts`, `stores/noManualOrder.test.ts`,
  `stores/noDuplicateMuteRule.test.ts` — пины владения; ни один шаг не имеет права заводить второй
  источник порядка/списка/правила мьюта.
- `boot.fullList.test.tsx` пинит именно ту полную загрузку, которую эта работа отменяет, —
  его сценарии переписываются, а не удаляются.
- Ответ прошлой сессии не применять: гварды `sessionGen` есть во всех сетевых путях владельца,
  новые пути обязаны их сохранить.
- `resetForLogout()` обязан сбрасывать **обе** новые структуры (счётчики и биты загруженности) —
  сегодня он гасит скалярные `loadedAll`/`serverCount`, и тест на это уже есть
  (`dialogsManager.pagination.test.ts:563`).

## Критерии приёмки

Автоматические:

- `go test ./...` в `backend/`, `npm test` + `npm run typecheck` в `web-client/` — зелёные.
- Страница архива, запрошенная с `folder_id=1`, отдаёт `count`, равный числу архивных диалогов, а не
  общему.
- `refresh()` на холодном старте выпускает запрос с `limit=20` и не поднимает `loadedAll`, пока
  сервер не сказал `is_end`.

Не проверяются автоматически (стенд `:38443`):

- список чатов на аккаунте с числом диалогов больше страницы догружается при скролле;
- у архива высота скроллбара сходится к реальной после первой страницы;
- пользовательская папка наполняется до конца при прокрутке;
- переключение папок сохраняет свой `scrollTop` у каждой.
