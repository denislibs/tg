# Волна 0: Solid в сборке и мост островов — план реализации

> **Для исполнителя:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ: `superpowers:subagent-driven-development`
> (рекомендуется) или `superpowers:executing-plans`. Шаги отмечаются чекбоксами.

**Цель:** стоковый Solid собирается нашим rolldown-Vite рядом с React, и есть
мост, которым Solid-компонент монтируется островом в React-дерево — с
обязательным `ErrorBoundary` и корректной смертью.

**Архитектура:** два JSX-рантайма в одной сборке разводятся по имени файла:
`*.solid.tsx` обрабатывает `vite-plugin-solid`, всё прочее — React. На стороне
TypeScript глобальный `"jsx": "react-jsx"` остаётся, а Solid-файлы переключаются
пофайловой прагмой `/** @jsxImportSource solid-js */`. Мост `mountSolid`
оборачивает компонент в `ErrorBoundary` внутри себя, поэтому смонтировать остров
без границы ошибок структурно невозможно.

**Стек:** `solid-js` 1.9.15, `vite-plugin-solid` 2.11.14, Vite 8 (rolldown),
vitest 4, happy-dom.

## Глобальные ограничения

Действуют на КАЖДУЮ задачу этого плана.

- Спецификация: `docs/superpowers/specs/2026-08-28-solid-migration-design.md`.
- **Только стоковый `solid-js`.** Форк tweb (`no-errors`) не вендорим: он
  отстал на 1.9.9 и в нём нет защиты `solid-js/store` от prototype pollution.
- **`ErrorBoundary` — обязательный элемент моста, а не рекомендация.**
- **Владелец сам снимает то, что создал.** Никакого «родитель размонтируется и
  унесёт» — это дефект, дважды воспроизведённый 2026-08-28.
- Комментарии и сообщения коммитов — по-русски.
- Каждый тест обязан краснеть на названной мутации; в сообщении коммита
  приводится РЕАЛЬНЫЙ вывод vitest, а не пересказ.
- Тесты гонять локальным бинарём: `./node_modules/.bin/vitest`
  (глобальный `npx vitest` подхватывает чужой vite из кэша npx и падает на sass).
- Волна 0 НЕ переводит ни одного продуктового компонента. Первый потребитель
  моста появляется в волне 1 (попапы). Мелкий лист (`Badge`, `Button`)
  конвертировать НЕЛЬЗЯ: Solid-компонент не вставляется в React-родителя
  напрямую, каждая граница — это настоящий DOM-хост с `dispose`, и на лист
  такой оверхед бессмыслен. Острова ставятся на крупных границах.

```tsx
/** @jsxImportSource solid-js */
import { ErrorBoundary } from 'solid-js'
import { render } from 'solid-js/web'
import type { JSX } from 'solid-js'

/**
 * Монтирует Solid-компонент в ГОТОВЫЙ DOM-узел и возвращает `dispose`.
 *
 * `ErrorBoundary` вшит в мост намеренно, а не оставлен на совесть вызывающего.
 * Причина: у tweb Solid форкнут (ветка `no-errors`), и в их сборке
 * `handleError` при отсутствии границы ЛОГИРУЕТ ошибку вместо `throw`
 * (`tweb/src/vendor/solid/dist/solid.js:979-982`). Мы берём сток, где на этом
 * месте `throw error` (`solid-js@1.9.15 dist/solid.js:1005`), — значит их
 * компоненты, портированные дословно, у нас роняли бы весь остров. Граница в
 * мосте даёт то же поведение штатным API, без форка и без отставания версий.
 *
 * Узлы, вставленные в `host`, снимает сам `dispose`: `render` в конце делает
 * `element.textContent = ""` (`solid-js/web@1.9.15 dist/web.js:199-202`).
 * Поэтому отдельная чистка хоста здесь была бы мёртвым кодом.
 */
export function mountSolid<P extends Record<string, unknown>>(
  host: HTMLElement,
  Component: (props: P) => JSX.Element,
  props: P,
): () => void {
  return render(
    () => (
      <ErrorBoundary
        fallback={(err) => {
          console.error('solid island error', err)
          return null
        }}
      >
        <Component {...props} />
      </ErrorBoundary>
    ),
    host,
  )
}
```

Создать `web-client/src/shared/solid/SolidIsland.tsx`:

```tsx
import { useLayoutEffect, useRef } from 'react'
import { mountSolid } from './mountSolid.solid'

/**
 * React-хост Solid-острова. Та же форма, которой у нас уже монтируются
 * ванильные порты (`components/chat/VanillaFeed.tsx`): узел-хост объявлен
 * `display: contents`, чтобы не появляться в бокс-дереве и не ломать flex
 * родителя, а инстанс поднимается layout-эффектом и гасится в его cleanup.
 *
 * Пропы едут снимком на монтирование: реактивность внутри острова — забота
 * самого Solid-компонента, а не React-родителя. Смена `component` пересоздаёт
 * остров (зависимость эффекта); смена `props` — намеренно нет, иначе остров
 * пересоздавался бы на каждый рендер родителя из-за нового объекта.
 */
export default function SolidIsland<P extends Record<string, unknown>>({
  component,
  props,
}: {
  // Возвращаемый тип — `unknown`, а не `JSX.Element`: этот файл собирается
  // React-рантаймом, и имя `JSX` здесь принадлежит React. Тип Solid-узла сюда
  // не затащить, не смешав два пространства имён.
  component: (props: P) => unknown
  props: P
}) {
  const hostRef = useRef<HTMLDivElement>(null)
  const propsRef = useRef(props)
  propsRef.current = props

  useLayoutEffect(() => {
    const host = hostRef.current
    if (!host) return
    // Единственное приведение во всём мосте, и оно ровно про это расхождение
    // пространств имён `JSX` (см. тип пропа выше), а не про обход типизации.
    // Узлы снимает сам dispose (`render` делает `element.textContent = ""`),
    // поэтому чистить хост здесь отдельно не нужно — это была бы мёртвая строка.
    return mountSolid(host, component as Parameters<typeof mountSolid<P>>[1], propsRef.current)
  }, [component])

  return <div ref={hostRef} style={{ display: 'contents' }} />
}
```

Создать `web-client/src/shared/solid/boundary.test.ts`:

```ts
import { readFileSync, readdirSync, statSync } from 'node:fs'
import { join, resolve } from 'node:path'
import { describe, expect, it } from 'vitest'

// Граница двух рантаймов держится ИМЕНЕМ ФАЙЛА, а имя ничего не проверяет само
// по себе. Этот скан — то, что делает соглашение обязательным: без него
// Solid-файл мог бы импортировать React, собраться и молча получить два
// рантайма в одном дереве. Тот же приём, что у `core/scrollWriters.test.ts`.
function walk(dir: string, out: string[] = []): string[] {
  for (const name of readdirSync(dir)) {
    const p = join(dir, name)
    if (statSync(p).isDirectory()) walk(p, out)
    else if (p.endsWith('.solid.tsx')) out.push(p)
  }
  return out
}

describe('граница двух JSX-рантаймов', () => {
  it('в *.solid.tsx нет импортов React', () => {
    const root = resolve(__dirname, '../..')
    const offenders = walk(root)
      .filter((p) => /from\s+['"]react(-dom)?['"]/.test(readFileSync(p, 'utf8')))
      .map((p) => p.slice(root.length + 1))

    expect(offenders).toEqual([])
  })

  it('скан вообще что-то видит — иначе пустой список ничего не доказывает', () => {
    expect(walk(resolve(__dirname, '../..')).length).toBeGreaterThan(0)
  })
})
```

## Чего волна 0 НЕ делает

- Не переводит ни одного продуктового компонента (см. глобальные ограничения).
- Не трогает Zustand: сторы переезжают вместе со своими экранами, начиная с
  волны 1 (§ 5 спецификации).
- Не добавляет живую проверку на стенде: волна 0 не меняет ничего видимого.
  Первая живая проверка — волна 1, когда островом станет настоящий попап.

## Признак, что волну можно закрывать

1. `vite build` собирает бандл с обоими рантаймами (задача 1, шаг 8) — это
   ответ на главный технический вопрос волны: совместим ли `vite-plugin-solid`
   с rolldown-вариантом Vite 8.
2. Мост `mountSolid` держит падение компонента и чисто умирает.
3. `SolidIsland` монтирует и гасит остров внутри React-дерева.
4. Граница двух рантаймов закреплена сканом, а не соглашением на словах.
5. Все четыре мутации проверены, вывод падений приложен к коммитам.
