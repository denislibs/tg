# Волна 1: база попапов классом и снос React-подтверждения — план реализации

> **Для исполнителя:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ: `superpowers:subagent-driven-development`
> (рекомендуется) или `superpowers:executing-plans`. Шаги отмечаются чекбоксами.

**Цель:** база попапов живёт классом, как у оригинала, и первый настоящий попап
(подтверждение) переехал с React — вместе со всеми пятью вызывающими.

**Архитектура:** у tweb попап — это класс `PopupElement`
(`components/popups/index.ts`, 494 строки) с императивным жизненным циклом
`createPopup → show → hide → destroy`. Содержимое бывает двух видов: простые
попапы строят DOM напрямую (`peer.ts`, `simpleConfirmation.ts` — **Solid там не
используется, проверено**), богатые монтируют Solid через `appendSolid`
(`index.ts:451-462`). Волна 1 берёт первый вид: базу и подтверждение.

**Стек:** TypeScript, наш `mountSolid` из волны 0, SCSS-порт `_popup.scss`.

## Глобальные ограничения

Действуют на КАЖДУЮ задачу.

- Спецификация: `docs/superpowers/specs/2026-08-28-solid-migration-design.md`.
  **Definition of Done — раздел 9 той же спеки, 14 пунктов. Он и есть критерий
  приёмки, читать до начала работы.**
- **Источник порта — исходник tweb, а не наш React-компонент** (§ 6a). Наш
  `ConfirmPopup.tsx` смотрится ТОЛЬКО на предмет сценариев, которых у оригинала
  нет; каждый такой сценарий либо обосновывается комментарием у строки, либо
  удаляется. Формулировка «сохранить текущее поведение» запрещена.
- Каждое портированное поведение несёт ссылку `file:line` на исходник tweb.
- Комментарии и сообщения коммитов — по-русски.
- Каждый тест обязан краснеть на названной мутации, и мутация **прогоняется
  фактически**. «Тест выглядит правильным» не считается: в волне 0 тест на
  `unmount` был зелёным при сломанном коде.
- Владелец сам снимает то, что создал; мёртвый код запрещён.
- Тесты гонять локальным бинарём: `cd web-client && ./node_modules/.bin/vitest run`.
- **Живая проверка на стенде обязательна** (DoD 10): волна меняет видимое.
  Стенд поднимается `docker compose -p msgrvanilla` с оверрайдом
  `docker-compose.vanilla.yml`, адрес `https://localhost:41443`.

### Задача 1: База `PopupElement`

**Файлы:**
- Создать: `web-client/src/components/popups/popupElement.ts`
- Создать: `web-client/src/components/popups/popupElement.test.ts`

**Источник:** `tweb/src/components/popups/index.ts` — читать целиком до начала.

**Интерфейсы (производит, на них опираются задачи 2-4):**
```ts
class PopupElement<E extends Record<string, unknown> = {}> {
  constructor(className: string, options?: PopupOptions)
  show(animate?: boolean): void
  hide(): void
  forceHide(): void
  protected destroy(): void
  protected setButtons(buttons: PopupButton[]): void
  protected appendSolid(cb: () => unknown): void       // поверх mountSolid волны 0
  static createPopup<T, A extends any[]>(ctor: new (...a: A) => T, ...a: A): T
}
type PopupButton = { text: string, callback?: () => void, isDanger?: boolean, isCancel?: boolean }
type PopupOptions = { closable?: boolean, overlayClosable?: boolean, withConfirm?: string, body?: boolean, title?: string }
```

**Портировать (объём этой волны):** конструктор и дерево (`:81-90` — element,
container, header, title, body, buttons), `setButtons` (`:247`), `show`
(`:330`), `hide` (`:391`), `forceHide` (`:409`), `destroy` (`:413`),
`appendSolid`/`appendSolidBody` (`:451-462`), `createPopup`.

**НЕ портировать в этой волне, и это назвать комментарием у класса:**
подтверждение при закрытии (`isConfirmationNeededOnClose`), `night`,
`withoutOverlay`, `reAppend`/`getPopups`, `Scrollable` внутри тела,
`confirmShortcutIsSendShortcut`. Каждый пункт — с причиной «нет потребителя в
волне 1», а не молча.

**Esc и Back берём НЕ как у tweb, а как у нас.** У оригинала это один
навигационный элемент (`appNavigationController`); у нас он расщеплён на
`core/hotkeys.pushEsc` и `useNavLayer`/`pushLayer` — ровно так уже сделано в
`shared/ui/Popup/Popup.tsx:96-101` и `helpers/overlayClickHandler.ts:104-105`.
Использовать существующее, третий способ не изобретать. Обосновать комментарием.

## Признак, что волну можно закрывать

1. База попапа живёт классом, Esc и Back работают через существующие механизмы.
2. Подтверждение портировано с `peer.ts`, а не переписано с нашего React.
3. **React-версия УДАЛЕНА**, число `.tsx` с импортом React уменьшилось, числа
   приведены (DoD 14).
4. Все мутации прогнаны фактически, выводы в телах коммитов (DoD 3, 4).
5. Живая проверка сделана и записана числами (DoD 10).
6. Непортированное названо комментарием с причиной, а не пропущено молча (DoD 2).

## Чего волна 1 НЕ делает

- Не трогает богатые попапы (`SendMediaPopup`, `StickerSetModal`, `QrModal`,
  `DatePickerPopup`, `WebAppModal`) — они у tweb на Solid, это волна 2.
- Не переводит `shared/ui/Popup` целиком: у него остаются другие потребители.
- `appendSolid` в базе появляется (он часть оригинала), но первый его настоящий
  потребитель — волна 2. Это назвать в комментарии у метода.
