# Этап 1B.1: страховочная сетка домена messages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть тестами непокрытые инварианты домена сообщений — **до** того, как он поедет на replay операций. Плюс починить один реальный баг, который разведка нашла попутно.

**Architecture:** Ничего не рефакторим. Пишем пины на то, что переезд обязан сохранить: коллизия оптимистичного `tentativeSeq` с серверным `seq`, дедуп по `seq`, жизненный цикл pending-кадров в проекторе, поведение outbox при ack/error/реконнекте. Плюс правим асимметрию, из-за которой воркерный кэш не знает о `client_msg_id`.

**Tech Stack:** TS strict, vitest + happy-dom, Zustand, SharedWorker.

## Почему сначала сетка, а не сразу переезд

Разведка показала: домен применяет каждый апдейт **дважды** (11 типов кадров: `worker.ts` → `messages.cacheX` и затем `storeProjection` → `messagesStore.applyX`), а оптимистичная отправка при этом **вообще не трогает SSOT воркера** — pending-кадры только бродкастятся (`realtime.ts:44-48`), бабл живёт исключительно в сторе. Переезд на операции обязан схлопнуть первое и как-то поступить со вторым.

Проблема в том, что самые хрупкие места этого домена **не покрыты**:

- **Коллизия `tentativeSeq`** — тестов нет вовсе. `appendOptimistic` берёт `maxSeq + 1` (`messagesStore.ts:224-225`), а `dedupAsc` схлопывает по `seq` через `Map` (`messagesStore.ts:54-57`), где побеждает последний вставленный. Значит чужое входящее сообщение с тем же `seq` **молча съедает оптимистичный бабл**. Это не гипотеза — это прямое следствие двух строк.
- **Дедуп по `seq`** — только косвенно, через тесты пагинации. Нет теста «два разных сообщения с одинаковым seq».
- **pending-кадры в проекторе** (`RT.pendingNew/Media/Fail/Retry/Remove`) — тестов нет ни одного, хотя это единственный путь появления бабла на экране.
- **Outbox** `connectionManager` (resend при реконнекте, удаление по ack/error, восстановление из IDB) — тестов нет.

Порядок ack↔echo, к счастью, покрыт в обе стороны (`messagesStore.ackEcho.test.ts:29,40`) — этот инвариант трогать не нужно.

### Task 5: Фикс коллизии tentativeSeq

**Files:**
- Modify: `web-client/src/stores/messagesStore.ts` (`appendOptimistic`)
- Modify: `web-client/src/stores/messagesStore.tentativeSeq.test.ts` (снять пометку «дефект», перевести тест 1 в проверку исправного поведения)

**Суть проблемы.** Оптимистичный бабл занимает ячейку `seq` в той же карте, что и настоящие сообщения (`dedupAsc` ключует по `seq`), хотя его `seq` — выдумка клиента. Любое совпадение уничтожает бабл, и пользователь видит, как его сообщение исчезает.

**Подход.** Развести пространства ключей: оптимистичный бабл не должен конкурировать за `seq` с серверными сообщениями. Минимальный способ, не трогающий сортировку — дедуп по составному ключу: для сообщения с `clientId` и без серверного `id` ключом служит `clientId`, для остальных — `seq`. Тогда бабл и входящее с тем же `seq` сосуществуют, а слияние по приходу эха продолжает работать через `applyIncoming` (он матчит по `clientId` и удаляет старый бабл явно, `messagesStore.ts:322-325`).

- [ ] **Step 1: Убедиться, что тест 1 из задачи 4 краснеет** после изменения его ожиданий на исправное поведение (бабл сохранился, в окне два элемента). Привести красный вывод.

- [ ] **Step 2: Реализовать** — правка `dedupAsc` (или места его вызова) по подходу выше. **Проверить, что не сломались**: `messagesStore.ackEcho.test.ts` (оба порядка), `messagesStore.sendStatus.test.ts`, `useMessageWindow.test.ts`, задачи 1 и 4 этого плана. Если какой-то из них требует правки — остановиться и сообщить: значит подход задевает инвариант, который держат другие тесты.

- [ ] **Step 3: Прогнать полный набор.** GREEN. Затем доказать укус: вернуть `dedupAsc` к ключеванию по `seq` → тест 1 обязан покраснеть; вернуть фикс.

- [ ] **Step 4: `npm test`, typecheck, oxlint, `npm run build`. Commit** — `fix(messages): оптимистичный бабл больше не вытесняется входящим с тем же seq`
