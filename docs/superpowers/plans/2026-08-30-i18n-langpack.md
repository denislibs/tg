# i18n на langPack: символические ключи, узлы вместо строк, сервер как источник

> **Для агентов:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ — `superpowers:subagent-driven-development`.
> Шаги отмечаются чекбоксами `- [ ]`.

**Цель:** заменить наш словарь «ключ = английская строка» на подсистему `langPack`
оригинала: символические ключи, `i18n(key, args)` возвращает УЗЕЛ, формы числа по
правилам языка, строки приезжают с сервера и обновляются по версии.

**Архитектура:** источник строк — `lang.ts` (английский, формат tweb) и таблица
переводов на бэкенде. Клиент получает `langPackDifference` конструкторами схемы,
кэширует и применяет; `I18n.strings` — единственная карта в памяти; `IntlElement`
владеет узлом во времени и перерисовывает его при смене языка.

**Стек:** TypeScript strict, vitest, Go 1.25 + goose, схема TL как общий источник.

**Источник порта:** `/Users/denisurevic/Documents/tweb` — `src/lib/langPack.ts`
(781 строка), `src/lang.ts` (4927), `src/langSign.ts` (65).

## Решения, принятые до плана

1. **Серверный langpack портируем.** Это работа и на бэкенде: хранение строк,
   версии, выдача разницы. Конструкторы и методы уже есть в общей схеме
   (`langPackString`, `langPackStringPluralized`, `langPackStringDeleted`,
   `langPackDifference`, `langPackLanguage`, `langpack.getLangPack`,
   `langpack.getDifference`, `langpack.getStrings`, `langpack.getLanguage`,
   `langpack.getLanguages`) — на бэкенде из этого не реализовано НИЧЕГО.
2. **React не трогаем.** `useT` и `t()` остаются; меняется только ТИП аргумента
   (`LangPackKey` вместо английской строки) и источник (`I18n.strings`). React
   уезжает своими волнами, переводить его дважды — работа впустую.
3. **Ключи меняем кодмодом.** 1085 вызовов в 182 файлах руками не пройти.

## Global Constraints

- **Все расхождения приводить к tweb** (DoD 2a спеки). Расхождение — работа, а не
  запись в долг; временная мера допустима только с НОМЕРОМ ЗАДАЧИ у строки.
- **Definition of Done** — `docs/superpowers/specs/2026-08-28-solid-migration-design.md` § 9.
  Особо: п. 4 (мутацию ФАКТИЧЕСКИ прогнать, вывод падения — в тело коммита),
  п. 10 (живая проверка), п. 13 (остаток назван задачей с номером).
- **Источник порта — файл tweb, а не наш нынешний i18n.** Наши `dict.*.ts` —
  это ДАННЫЕ (переводы), которые переезжают; наша `index.tsx` источником
  поведения не является.
- **Кодмод не коммитится «как получилось».** Каждый прогон — отдельный коммит по
  подсистеме, с прочитанным диффом. Кодмод, который нельзя перечитать глазами по
  частям, к слиянию не принимается.
- **Ни один коммит не оставляет приложение сломанным.** Старый `t()` живёт до
  задачи 9; до неё обе формы ключа обязаны работать.
- **Комментарии и сообщения коммитов — по-русски**, объясняют ПОЧЕМУ.
- `git add -A` запрещён: индекс ворктри общий с другими агентами.

- [ ] **Шаг 1: собрать ключи**

Для каждого из 953 ключей нынешнего `dict.ru.ts` определить символический ключ:
если строка **дословно** совпадает со значением какого-то ключа в
`tweb/src/lang.ts` — берётся ключ ОРИГИНАЛА (так уже сделано в волне 2:
`CurrentSession`, `OtherSessions`, `TerminateAllSessions` и другие взяты из
`lang.ts:1444-1465`). Если совпадения нет — новый ключ по правилам именования
оригинала (`Раздел.Подраздел.Смысл`).

Совпадения искать МАШИННО и проверять глазами: строка может совпасть случайно
(`'Delete'`), и тогда ключ оригинала не подходит по смыслу.

- [ ] **Шаг 2: тест — карта полная и однозначная**

```ts
import { describe, expect, it } from 'vitest'
import { lang } from '../lang'
import { LEGACY_KEY_MAP } from './legacyKeyMap'
import ru from './dict.ru'

describe('карта миграции ключей', () => {
  it('покрывает каждый ключ нынешнего словаря', () => {
    const missing = Object.keys(ru).filter((k) => !(k in LEGACY_KEY_MAP))
    expect(missing).toEqual([])
  })

  it('не отображает два разных ключа в один', () => {
    const seen = new Map<string, string>()
    const collisions: string[] = []
    for (const [legacy, key] of Object.entries(LEGACY_KEY_MAP)) {
      const prev = seen.get(key)
      if (prev && prev !== legacy) collisions.push(`${key}: ${prev} / ${legacy}`)
      seen.set(key, legacy)
    }
    expect(collisions).toEqual([])
  })

  it('каждый символический ключ есть в английском источнике', () => {
    const orphans = Object.values(LEGACY_KEY_MAP).filter((k) => !(k in lang))
    expect(orphans).toEqual([])
  })
})
```

- [ ] **Шаг 3: тест — ключи, взятые у оригинала, написаны как у оригинала**

Читает `tweb/src/lang.ts` и сверяет: если наш ключ есть у tweb, английская
строка обязана совпадать дословно. Расхождение здесь означает, что ключ взят по
похожести, а не по смыслу.
