## Мутации (все краснят, вывод vitest реальный)

1. **Плеер до onAnimationEnd** — `Promise.all([canPlayThrough])` +
   `Promise.all([promise])` (обе половины гейта; одиночная мутация внутреннего
   гейта выживает — гейт намеренно двойной, как в tweb):
   `× canplay до конца полёта плеера не даёт... AssertionError: expected <div …> to be null`
   → `Tests  1 failed | 6 passed (7)`.
2. **loop-порог 60 → 0**:
   `× duration < 60 → loop — AssertionError: expected false to be true`
   → `Tests  1 failed | 6 passed (7)`.
3. **is-buffering не снимается** (закомментирован `classList.remove`):
   первый вариант теста мутацию ПРОПУСКАЛ (класс оставался на аспектере, а
   ассерт смотрел на нового родителя после репарента в плеер) — ассерт усилен
   до «`.is-buffering` нет нигде в мувере», после чего:
   `× нехватка данных... AssertionError: expected <div …(2)> to be null`
   → `Tests  1 failed | 6 passed (7)`.

## Замечания

- Цикл модулей `mediaViewer/base ↔ lib/mediaPlayer` идентичен tweb (их
  VideoPlayer импортирует mediaViewer/base ради типа); все взаимные ссылки —
  рантайм, hoisted-функции. `replaceButtonIcon` экспортирован из base
  (в tweb живёт в components/button.ts — вынос в отдельные icon.ts/button.ts
  оставлен финальной сверке Task 17, если захочется 1:1 раскладку файлов).
- `duration` у нашего бэка для обычных видео часто 0/отсутствует
  (длительность считает клиент только для голосовых — см. `core/gifs.ts`):
  `(duration ?? 0) < 60` тогда даёт loop всем таким видео. Поведенчески
  безвредно, но Task 16 стоит прокинуть честную длительность из payload,
  где она есть.
- Тексты пунктов меню скоростей — `t('Normal')`/`2x`: ключа `Normal` в
  `dict.ru.ts` нет (упадёт в английский фолбэк) — та же ситуация, что у
  Forward/Download/Delete из Task 14; довесок словаря — Task 17.
- Стрелки в фуллскрине сикают ±10с (tweb-дефолт seekForward/seekBackward);
  старый лайтбокс сикал ±5с — уходит вместе с ним в Task 16.
