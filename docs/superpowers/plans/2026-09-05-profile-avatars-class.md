# Шапка профиля классом `PeerProfileAvatars` — план реализации

> **Для агентов:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ: `superpowers:subagent-driven-development`.
> Шаги помечены чекбоксами (`- [ ]`).

**Цель:** заменить самодельную React-карусель аватаров внутри `UserInfoPanel.tsx`
дословным портом класса tweb `src/components/peerProfileAvatars.ts`, и заодно
свести два разошедшихся механизма сворачивания шапки в один.

**Место в программе:** волна 3 Solid-миграции
(`docs/superpowers/specs/2026-08-28-solid-migration-design.md`), этап 2 (профиль),
**шаг 1 из двух**. Шаг 2 — Solid-порт `peerProfile.tsx` — пишется отдельным планом
после закрытия этого. Порядок именно такой, потому что в оригинале имя и статус
пира живут ВНУТРИ узла карусели (`avatars.info`, tweb `peerProfile.tsx:217-272`):
сделать карточку первой значило бы собрать её вокруг нашей самоделки и потом
переделать.

**Архитектура:** карусель в tweb — императивный класс, а не Solid-компонент.
Портируем его классом же (`web-client/src/components/peerProfileAvatars.ts`),
зависимости он получает через конструктор (как `components/avatar.ts:104`
получает `managers`), в React-панель встаёт через `core/hooks/useImperativeIsland`.
После этого шага React владеет только оболочкой панели (портал, шапка сайдбара,
оверлеи) — узлом шапки-аватаров владеет класс.

**Оригинал:** `/Users/denisurevic/Documents/tweb/src/components/peerProfileAvatars.ts`
(974 строки). Разбор устройства с адресами — `docs/tweb/right-sidebar.md` § 3.3.

## Global Constraints

- **Источник порта — tweb, а не наш React.** В каждом коммите — ссылки
  `file:line` на оригинал для каждого портированного поведения (DoD п.1).
  Формулировка «сохрани текущее поведение» запрещена: так в порт протаскиваются
  наши недоделки.
- **Расхождение либо отсутствует, либо объявлено комментарием ПРЯМО У СТРОКИ**
  с причиной и адресом оригинала (DoD п.2). Молчаливых расхождений нет.
- **Норма проводки:** каждая строка проводки обязана краснить тест, если её
  испортить. В теле КОММИТА — транскрипт мутаций: что испортил, какой тест
  покраснел, с именем теста и реальным выводом vitest (DoD п.3, п.4).
- Комментарии по-русски, по стилю соседних файлов.
- React внутри класса не появляется. `framer-motion`, MUI не возвращать.
- Мёртвый код удалять сразу: у снесённых компонентов не остаётся ни файла, ни
  типов, ни хуков-питателей без потребителей.
- Работа только в ворктри
  `/Users/denisurevic/Documents/messenger-denis/.claude/worktrees/solid-wave-3`,
  ветка `feat/profile-avatars-class`. Контейнеры не поднимать, конфиги
  (docker-compose, nginx, vite, vitest) не трогать, проверки не обходить.
- Индексировать только свои пути; индексация всего дерева запрещена (индекс
  ворктри общий с фоновыми агентами).
- Перед словом «готово» в КАЖДОЙ задаче: `npx vitest run` (весь набор, не
  выборочно), `npx tsc --noEmit`, `npx vite build` — все три из `web-client/`.

  **Заменено по факту (координатор, начиная с задачи 3):** гонять весь набор
  `npx vitest run` (531 файл/~4500 тестов на момент плана) в КАЖДОЙ
