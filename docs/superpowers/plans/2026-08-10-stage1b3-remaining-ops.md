# Этап 1B.3: остальные кадры на операции — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести домен сообщений до одного применения: перевести на операции оставшиеся типы кадров и снять двойную интерпретацию окончательно.

**Architecture:** Протокол из 1B.2 расширяется операцией `patch` — частичное изменение полей сообщения по `msgId`. Это ключевое отличие от `replace`: воркерная модель **беднее витринной**, потому что часть данных живёт только на главном потоке (свой голос в опросе, деривированный `mine` у реакций, локальное превью `localUrl`, резолвнутое превью ответа). Замена целого сообщения их сотрёт — патч сохранит.

**Tech Stack:** TS strict, vitest + happy-dom, Zustand, SharedWorker + rootScope.

## Что говорит предыдущий этап

Финальное ревью 1B.2 назвало это прямо: трёх операций (`insert`/`replace`/`remove`) не хватит. `edit`/`reaction`/`poll` через `replace` из SSOT молча сотрут main-thread-обогащения, которые сегодняшние `applyEdit`/`applyReaction`/`applyPollUpdate` сохраняют, потому что они — field-patch, а не замена. Для `read`/`media_read` (массовая смена флага по диапазону) понадобится range-операция вместо россыпи замен.

Ядро протокола (адресация окон по ключу, гейт «окно загружено», идемпотентность) переносится как есть.

## Global Constraints

- **Обогащения главного потока не теряются.** Это главный критерий всего этапа. Для каждого переводимого типа кадра сначала выписывается, какие поля витринной модели воркер не знает, и только потом пишется операция. Если для какого-то типа список непустой — это `patch`, а не `replace`.
- **Поведение не меняется.** Все существующие тесты домена обязаны пройти **без единой правки**. Правка любого — стоп и сообщение (BLOCKED).
- Несущий инвариант дедупа сохраняется: неподтверждённый бабл — `clientId` + `id < 0`.
- Сырые кадры продолжают рассылаться параллельно (как в 1B.2) — переключение проектора на операции для каждой группы обратимо одной строкой.
- Операции типизированы; пропуск ветки в переигрывателе ловится компилятором.
- `slicedArray.ts` — вендор, не трогать.
- Комментарии по-русски, в стиле окружающего кода.
- Команды из `web-client/`: `npm test`, `npm run typecheck`, `npx oxlint <файлы>`, `npm run build`.
  `npm run lint` выходит с кодом 1 и на main (вендореный `middleware.ts`) — ворота: не добавлять НОВЫХ находок.
