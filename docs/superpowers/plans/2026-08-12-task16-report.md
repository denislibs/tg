## Точки входа

- **Чат (Chat.tsx)**: `feedFns.openLightbox` теперь собирает items
  `collectLightboxItems` (элементы соседей — по `[data-mid] .attachment` в
  отрендеренных баблах, как tweb bubbles.ts:3744-3800) и зовёт контроллер с
  `reverse: true` (tweb bubbles.ts:3843). Колбэки:
  - `jumpToMessage` → `jumpToSeq(item.seq)` (существующий прыжок ленты;
    `ViewerItem` получил поле `seq` — jump ходит по seq, forward/delete по id);
  - `onForward`/`onDelete` → существующие `openForwardFor`/`openDeleteFor`
    (React-попапы); подтверждение попапа закрывает вьювер через
    `viewerActionCloseRef` (обёртка `doDelete`/`doForward` у
    `<ChatMsgActionPopups>`) — как tweb showForwardPopup/PopupDeleteMessages;
  - `loadMoreMedia` → REST `GET /chats/{id}/media?filter=media` (newest-first,
    offset-пагинация): страницы докручиваются до якоря и loadCount за ним,
    кэш живёт одно открытие; `ListLoader` с `reverse: true` раскладывает сам.
  - Смена чата/unmount → `closeMediaViewer()`.
- **Профиль (UserInfoPanel)**: `openAvatarViewer` премеряет still-фотографии
  (naturalWidth/Height; src уже показан шапкой — кэш) и открывает items с
  `media.url` (мимо конвейера); видео-аватар (tweb photo_video) = gif-режим
  вьювера (muted-loop без плеера), как играл старый лайтбокс.
- **SharedMedia**: клик по тайлу → те же items через `messageToViewerItem`
  (имена авторов — из зеркала peersStore; попутно закрыт латентный рассинхрон
  индекса грида с отфильтрованным списком). jump/forward/delete не
  пробрасываются — их не было и у старого лайтбокса (поведение сохранено).

## Скрытие миниатюры — сверено с tweb

`grep visibility tweb/mediaViewer/base.ts` показал: tweb **не прячет миниатюру
источника вовсе** — visibility трогается только у мувера; миниатюру на время
просмотра накрывает сам вьювер (`.media-viewer` rgba(0,0,0,.88)), при полёте
её пиксель-в-пиксель закрывает мувер. Прячутся только плавающие оверлеи бабла
(`.video-time`, `.time.is-floating`, `.video-play`) — `hideFloatings`/
`revealHiddenFloatings`, порт уже жил в нашем base.ts (Task 11+). Поэтому
useLightbox-механика `el.style.visibility='hidden'` + `onClosingStart` умерла
вместе со старым API — новый путь 1:1 tweb: **не прятать ничего**. Баг
UserInfoPanel (лайтбокс без `onClosingStart` навсегда прятал миниатюру при
закрытии по Back) умер вместе с механикой.

## z-index — решение

tweb даёт `.media-viewer-whole` `z-index: 4` (в tweb весь прочий хром ниже).
У нас вьювер монтируется в общий body рядом с #root, где слои приложения
заняли сотни/тысячи (панели 1900, меню 2001, **попапы 4090**, медиа-редактор
4200, звонок 5000) — с «4» вьювер нырял бы под всё. Задокументированное
отступление — в партиале-мосте **`styles/tweb/_bridge.scss`** (НЕ в base.ts и
НЕ в портированном `_mediaViewer.scss`): `.media-viewer-whole { z-index: 4000 }`
— значение старого модуля: выше меню/панелей, ниже попапов (попапы
подтверждения удаления/пересылки, открытые ИЗ вьювера, обязаны быть поверх).

## Замечания

- Дозагрузка listLoader «в новее» работает от любого якоря (страницы идут с
  нулевого offset и покрывают новую сторону раньше якоря); якорь секретного
  чата в REST-фильтр `media` не попадает — вьювер честно листает только окно
  (поведение старого лайтбокса).
- Топбар вьювера shared media теперь показывает автора (из peersStore) — у
  старого лайтбокса там было пусто при той же дате; сознательное сближение с
  tweb, не регресс.
- `.mediaTile` шаред-грида не несёт tweb-класс `grid-item`, поэтому
  hideFloatings-контекст `grid-item` там не срабатывает (плашка длительности
  не гаснет на полёте) — косметика, добить при порте searchSuper-грида.
