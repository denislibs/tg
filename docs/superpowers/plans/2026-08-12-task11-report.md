## Тесты (TDD, happy-dom + fake timers) — `base.mover.test.ts`, 10 тестов

RED наблюдался (метод отсутствовал: `TypeError: this.setMoverToTarget is not a
function`, 10/10 fail), затем GREEN. Transitions в happy-dom не играют —
`waitForMoverTransition` резолвится страховочным таймером, тесты проверяют
именно этот путь. Пины: стартовый transform (translate3d(rect)+scale3d(50/400,
40/320)), сайз мувера в containerRect; counter-scale аспектера (scale3d(8,8,1));
nav-ветка без scale3d со стартом за экраном + класс `moving`; целевой кадр
translate3d(containerRect)+scale3d(1,1,1) и borderRadius снят; финал по таймеру
center+active+applyCenterStyles; needOpacity (источник вне вьюпорта скролла) —
opacity 0→''; клип inset() на wrapper (не на мувере) → inset(0px) → снятие;
закрытие с re-measure (мок getBoundingClientRect меняется между открытием и
закрытием — целевой transform от НОВОГО rect) + `backwards` на whole + уборка
cssText; moveTheMover — `.moving`, отъезд на −width/windowW, удаление wrapper.

Мутации (все три краснят, реальный вывод vitest):

1. Снят counter-scale аспектера (cssText без transform):
   ```
   FAIL … аспектер несёт counter-scale (rect-размер × scale3d(containerRect/rect))
   AssertionError: expected '' to be 'scale3d(8, 8, 1)'
   ```
   (падают также 8 смежных тестов — аспектер участвует в целевом кадре).
2. Снят re-measure (в `if(!rect)` подставлен rect `content.media` вместо цели):
   ```
   FAIL … стартовый transform = translate3d(rect) + scale3d(rect/containerRect) …
   AssertionError: expected 'translate3d(300px,60px,0) scale3d(1,1…' to contain 'translate3d(100px,200px,0)'
   FAIL … re-measure: целевой transform закрытия считается от НОВОГО rect источника
   Error: Test timed out in 5000ms.
   ```
3. Снят страховочный таймер `waitForMoverTransition` (:1839):
   ```
   FAIL … целевой кадр: … финал по таймеру — center+active — AssertionError: expected true to be false
   FAIL … toggleWholeActive(false) вызван; уборка по таймеру … — Error: Test timed out in 5000ms.
   ```
   (5 тестов: без таймера в happy-dom финал/уборка не наступают никогда).

Мутация «снять offsetLeft-барьер» тестами не ловится (в happy-dom рефлоу-порядок
кадров ненаблюдаем) — по плану задачи взяты две альтернативные ветки (№2, №3).
