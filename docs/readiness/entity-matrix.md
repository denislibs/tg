# Матрица сущностей и действий: tweb против нас

Снято 2026-08-16. Метод: сравнение **поверхностей менеджеров** (`tweb/src/lib/appManagers/*`
против `web-client/src/core/managers/*`), контекст-меню и экранов, плюс
[база знаний по tweb](../tweb/README.md).

**Как читать.** ✅ есть · ❌ нет · ⚠️ есть частично или иначе · — вне продукта ·
❓ по коду не определить.

**Важная оговорка про метод.** Наличие метода менеджера доказывает, что возможность есть
**в коде**. Выведена ли она в интерфейс — отдельный вопрос: где знаю, помечено; где нет — ❓.
Обратное тоже верно: пункт может отсутствовать в меню при живом API (так вышло с избранными
стикерами — `stickersManager.fave` есть, пункта в меню сообщения нет).

Действия над **сообщением** — в отдельном документе:
[`message-matrix.md`](message-matrix.md).

## Сводка: где дыры

По убыванию заметности для пользователя.

1. **Диалог**: нет «пометить прочитанным», а «добавить в папку» спрятано в редактор папки —
   два клика, которые делают каждый день.
2. **Группа**: нет журнала действий, антиспама, скрытия участников. Журнал — заметнее всего для админов.
3. **Уведомления**: нет экрана исключений (заглушить конкретный чат при этом можно).
4. **Пользователь**: нет общих чатов и частых контактов.
5. **Стикеры**: нельзя переупорядочить наборы.
6. **Истории**: нет альбомов и скрытия историй пира.
7. **Приватность**: нет веб-сессий и смены login-email.
8. **Экономика Telegram** (подарки, платежи, премиум-стикеры) — крупнейший блок, но, вероятно,
   вне продукта: решить и вычеркнуть, чтобы он перестал считаться отставанием.

## Как поддерживать

Матрица снята из кода, значит проверяема заново тем же способом: сравнить списки методов
менеджеров с обеих сторон. Клетки ❓ требуют стенда. При добавлении менеджера или экрана —
обновлять здесь же.
