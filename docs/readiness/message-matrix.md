## А. Отправка: что несёт каждый путь

Строки — типы контента, столбцы — свойства отправки. Клетка ❌ означает, что поле просто
не доезжает до `sendMessage`.

| Тип | Отправка | Как ответ | Цитата | В тред | Молча | Эффект | От имени канала | Где |
|---|---|---|---|---|---|---|---|---|
| Текст | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `useChatSend.ts::sendReal` |
| Фото | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `::onPickFile` → `messages.sendFile` |
| Видео | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | там же |
| Файл | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | там же |
| Голосовое | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `::rec.onComplete` |
| Кружок | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | там же |
| Стикер | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `::sendSticker` |
| GIF | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `::sendGif` (и saved, и Tenor) |
| Гео / venue | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `::sendGeo` |
| Live-гео | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ | `::sendGeo` → `sendGeoLive` (REST) |
| Контакт | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | `::sendContact` |
| Опрос | ✅ | ✅ | ✅ | ✅ | ✅ | — | ✅ | `useChatPopups::openPoll` → `sendPoll` (REST) |
| Пост канала | ✅ | ❌ | ❌ | ✅ | ❌ | ❌ | — | `::send` → `channels.post` (REST) |

**Как закрыто.** Портирован **пакет параметров отправки** — tweb `MessageSendingParams`
(`lib/appManagers/appMessagesManager.ts:255`) + `Chat.getMessageSendingParams()`
(`components/chat/chat.ts:1352`). Наши `messages.sendText`/`sendFile`/`sendPoll`/`sendGeoLive` и
`secret.sendText`/`sendMedia` принимают его одинаково; вызывающий (`useChatSend`) собирает пакет
ОДИН раз (`getMessageSendingParams()`) и раздаёт всем путям. Проводные поля кадра
(`reply_to_id`, `reply_quote_*`, `thread_root_id`, `silent`, `effect`, `send_as_chat_id`)
типом изъяты из «остальных аргументов» — передать их мимо пакета нельзя. Держат
`core/sendingParams.test.ts` (скан: вызов отправки без пакета краснеет),
`core/hooks/useChatSend.test.tsx` (каждый путь по отдельности) и
`core/managers/messages/pending.test.ts` (оптимистичный бабл несёт ответ до ack).

**Оставшиеся ❌ — не забывчивость, а отсутствие поля на бэкенде:**
- **Live-гео, `silent`/`effect`.** Путь идёт REST'ом (нужен `msg_id` для последующих обновлений
  трансляции), а `sendBody` в `chat_handler.go` этих двух полей не принимает — их несёт только
  WS-кадр. Ответ/цитата/тред/send-as через тот же REST доезжают.
- **Опрос, `effect`.** Бэкенд снимает эффект с типа `poll` по whitelist (`sanitizeEffect`,
  `usecase/chat/sanitize.go:29-32`) — как и Telegram, который эффекты на опросах не показывает.
  Предмета нет.
- **Пост канала.** `POST /channels/{id}/messages` принимает ровно `{text, entities,
  client_msg_id}` (`channel_handler.go:65-71` → `PostToChannel` с позиционной сигнатурой).
  Довести пакет = менять сигнатуру usecase и её тест-вызовы — отдельная работа по бэкенду.
  Плашку ответа этот путь при этом гасит.

**Плашка ответа** сбрасывается после отправки ЛЮБЫМ путём — порт tweb
`ChatInput.onMessageSent() → clearHelper()` (`components/chat/input.ts:4067,4100`), который в
оригинале зовётся из каждой точки отправки (текст `:4355`, документ/стикер/гиф `:4355`, запись
голоса `chatRecording.ts:239`, попап медиа `newMedia.ts:996`, меню `contextMenu.ts:934`).
У нас это `useChatSend::onMessageSent`.

**Секретные чаты.** Ответ и тред теперь едут (`reply_to_id`/`thread_root_id`/`silent` — это
метаданные маршрутизации, сервер их и так знает; мешала только узкая типизация
`SecretDeps.conn.sendMessage`, то есть проводка). **Цитата не едет и не должна** в текущем
формате: `reply_quote_text` — это ТЕКСТ оригинала, и в открытом кадре он отдал бы серверу кусок
плейнтекста E2E-переписки. Правильное место цитаты — внутри шифруемого payload
(`encryptPayload({text, entities})`), это смена формата E2E с версионированием на обе стороны —
отдельная работа (~0.5 дня клиента, без бэкенда: payload непрозрачен для сервера).

Там же остаётся вторая дыра (не трогалась): таймер самоуничтожения (`ttlSeconds`) доезжает
только у текста. Медиа секретного чата уходит с жёстко зашитым `ttlSeconds: null` — и голосовое,
и файлы с фото. То есть выставленный таймер на медиа просто не применяется.

## Б. Пункты меню: наши условия против tweb

Сравнение нашего `regularMenuItems` (`useMessageActions.tsx:610-690`) с
[`message-interactions.md` §1.4](../tweb/message-interactions.md).

### Показываем там, где tweb не показывает

| Пункт | У нас | В tweb | Следствие |
|---|---|---|---|
| Copy | всегда, кроме секретного (`:617`) | `message.message && !noForwards` — **только если есть текст** | «Копировать» на стикере, кружке, фото без подписи копирует пустоту |
| Edit | любое своё сообщение (`:614`) | `canEditMessage(msg, 'text')` | «Изменить» на своём стикере; что произойдёт при попытке — ❓ |
| Pin | всегда в реальном чате (`:631`) | `canPinMessage && !messageService && !frozen` | пункт виден без проверки прав — ❓ упадёт или молча ничего |
| Forward | всегда, кроме секретного (`:672`) | `!noForwards && !messageService` | «Переслать» на сервисном сообщении — ❓ показываем ли мы там меню вообще |

### Нет у нас

| Пункт tweb | Что это | Тип, которого касается |
|---|---|---|
| Quote (#7) | отдельный пункт «Цитировать» при выделении | текст |
| AddToFavorites / DeleteFromFavorites (#11, 12) | избранные стикеры из меню сообщения | стикер |
| ViewReplies / ViewAllReplies (#9, 10) | переход в тред из бабла | любой в группе с обсуждением |
| Copy Selected Text, Search Selected (#17, 18) | работа с выделением | текст |
| Copy Link / Username / Hashtag (#20–22) | контекст по якорю под курсором | текст со ссылками |
| Send Now, Edit Schedule Time (#4–6) | управление отложенными | любой отложенный |
| Poll Stats (#31) | статистика опроса | опрос |
| Reacted list (#38) | «кто реагировал / прочитал» в группах | любой |
| Message contains emoji pack (#43) | набор кастомных эмодзи из сообщения | текст с кастом-эмодзи |

Цитирование у нас всё же есть, но иначе: выделение подхватывается автоматически при обычном
«Ответить» (`useMessageActions.tsx:126-168`). Отдельного пункта нет — это осознанное упрощение
или недоделка, надо решить.

## Как поддерживать

Матрица снята чтением кода, значит проверяема заново тем же способом. Клетки ❓ требуют стенда —
их немного, и они помечены. При правке путей отправки или условий меню обновлять здесь же,
в том же изменении.
